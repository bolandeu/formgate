# Капча (proof-of-work ALTCHA)

Документ для разработчика сайта и для инструментов, которые собирают формы (сборщики вёрстки и генераторы сайтов): как включить proof-of-work, что добавить на сайте и как проверить результат. Контракт формы — `docs/integration.md`, раздел 6.

## 1. Что это и сколько стоит посетителю

С `require_pow` каждая заявка требует небольшой работы от отправителя. Клиент formgate решает задачу сам, в фоне, пока посетитель заполняет форму. Протокол открытый — [ALTCHA](https://altcha.org).

- Посетитель ничего не видит и не нажимает. Решение занимает около полусекунды на телефоне (при `pow_max_number` по умолчанию, `50000`).
- Куки нет. Внешнего сервиса нет: задачу выдаёт и проверяет сам шлюз, ключ подписи — тот же, что у метки времени.
- Персональные данные никуда не уходят. Клиент общается только со шлюзом, с тем же адресом, что у формы.
- Заявка без верного решения не теряется: она получает обычный ответ «успех», не доставляется и попадает в спам-лог. Оператор может её выпустить (раздел 6).
- Нужен безопасный контекст: сайт по HTTPS (или `localhost`). Браузер даёт `crypto.subtle` только там.

## 2. Включить

`require_pow` работает поверх метки времени: нужен `require_token`. Без него шлюз не принимает настройки.

**Lite.** В файле настроек (`formgate.php`, `docs/lite-setup.md`, раздел 3), раздел `project`:

```php
'project' => [
    'require_token' => true,
    'require_pow' => true,
    'pow_max_number' => 50000,
],
```

| Настройка | По умолчанию | Что делает |
| --- | --- | --- |
| `require_token` | `false` | Проверка метки времени. Обязательна для `require_pow`. |
| `require_pow` | `false` | Заявка без верного решения идёт в спам-лог. |
| `pow_max_number` | `50000` | Сколько чисел перебирает клиент, самое большее. От `1000` до `10000000`. Больше — дольше работа на телефоне. |

**Pro.** Командами оператора (`docs/pro-setup.md`, разделы 4 и 7), по одной на настройку:

```sh
docker compose exec web php bin/formgate project:set <ключ> project.require_token true
docker compose exec web php bin/formgate project:set <ключ> project.require_pow true
docker compose exec web php bin/formgate project:set <ключ> project.pow_max_number 50000
```

`project:set <ключ> project.require_pow true` без `require_token` команда отклоняет, файл проекта не меняется.

После включения `GET <адрес формы>?token` отдаёт в ответе поле `challenge`. Проверьте:

```sh
curl -s -H 'Origin: https://site.ru' 'https://<хост-шлюза>/f/<ключ-проекта>?token'
```

В ответе есть `token`, `min_seconds` и `challenge` с `maxnumber`, равным `pow_max_number`.

> `require_token` и `require_pow` действуют на **все** формы проекта. Подключите клиент на каждой форме до включения.

## 3. Сайт: режим «невидимо»

Ничего добавлять не нужно. Клиент formgate, привязанный к форме, сам получает задачу вместе с меткой, решает её в фоне и кладёт решение в `__pow`. Разметка формы та же, что без капчи:

```html
<form action="https://<хост-шлюза>/f/<ключ-проекта>" method="post" data-formgate>…</form>
```

Три вида клиента (`docs/integration.md`, раздел 6):

- **npm-пакет** (Vite, webpack): `import { bindForm } from 'formgate/client'`. Решатель входит в бандл.
- **Astro-интеграция** `formgate/astro`: привязывает формы сама. С `bind: false` привяжите формы через `bindForms()` из `formgate/client`.
- **`formgate.js`** на статическом сайте: `<script src="/formgate.js" defer></script>`.

Клиент берёт задачу при привязке к форме и заново после каждой отправки, так что к нажатию кнопки решение уже готово. Если посетитель отправил форму раньше, чем решение готово, клиент ждёт его.

## 4. Сайт: режим «виджет»

Атрибут `data-formgate-pow="widget"` на форме показывает виджет ALTCHA: посетитель видит, как идёт решение. Атрибут читает клиент (все три вида), больше ничего включать не нужно.

```html
<form action="https://<хост-шлюза>/f/<ключ-проекта>" method="post" data-formgate data-formgate-pow="widget">
  <label>Телефон <input type="tel" name="phone" required></label>
  <button type="submit">Отправить</button>
</form>
```

**Где виджет.** Клиент создаёт элемент `<altcha-widget name="__pow">` сам и ставит его перед кнопкой отправки формы (`<button>` без `type` или `type="submit"`). Кнопка может лежать в обёртке: виджет встанет рядом с ней, перед самой кнопкой. Если кнопки нет, виджет идёт в конец формы. Посетителю не нужно нажимать на виджет: решение стартует само.

**Как загружается модуль виджета.** Он грузится только для форм с атрибутом; форма без атрибута код виджета не получает.

- **npm-пакет и Astro:** клиент подгружает модуль `formgate/client/pow-widget` динамическим `import`, сборщик выделяет его в отдельный чанк. Ничего подключать не надо.
- **`formgate.js`:** модуль — файл `formgate-pow-widget.js`, он грузится из той же папки, что и `formgate.js`. Lite кладёт оба файла рядом. На сайте с Pro скопируйте оба файла из пакета (`formgate/lite/formgate.js` и `formgate/lite/formgate-pow-widget.js`) в одну папку.

Если модуль не загрузился, форма всё равно отправляется, но без `__pow`: заявка уйдёт в спам-лог с причиной `pow_missing` (раздел 6).

**Стили.** Виджет — обычный блок в форме, `max-width` по умолчанию `320px`. Настраивается CSS-переменными `--altcha-*`; задайте их на `altcha-widget` или на форме. В `:root` не задавайте: виджет вставляет свои стили позже и перебивает их.

```css
altcha-widget {
  --altcha-max-width: 100%;
  --altcha-border-radius: 8px;
  --altcha-color-primary: #0a5;
  --altcha-color-success: #0a5;
  margin-block: 1rem;
}
```

Основные переменные:

| Переменная | Что задаёт |
| --- | --- |
| `--altcha-max-width` | ширина блока (`320px`) |
| `--altcha-padding` | внутренний отступ (`0.75rem`) |
| `--altcha-border-width`, `--altcha-border-color`, `--altcha-border-radius` | рамка |
| `--altcha-color-base`, `--altcha-color-base-content` | фон и текст |
| `--altcha-color-primary` | цвет кнопок и фокуса |
| `--altcha-color-success`, `--altcha-color-error` | цвета успеха и ошибки |
| `--altcha-color-neutral`, `--altcha-color-neutral-content` | нейтральные цвета |
| `--altcha-checkbox-size`, `--altcha-checkbox-border-color` | размер и рамка флажка |
| `--altcha-spinner-color` | цвет индикатора |

Полный список переменных — в стилях пакета `altcha` (`altcha/altcha.css`) и в [документации ALTCHA](https://altcha.org/docs/). Блок наследует `font-family` и `font-size` формы.

**Светлая и тёмная тема.** Цвета по умолчанию заданы функцией `light-dark()`, поэтому они следуют CSS-свойству `color-scheme`. Сайт с тёмной темой ставит его сам:

```css
:root { color-scheme: light dark; }          /* по настройке системы */
:root[data-theme="dark"] { color-scheme: dark; } /* по переключателю сайта */
```

Если сайт рисует тему своими цветами, задайте `--altcha-color-base` и `--altcha-color-base-content` под обе темы.

Атрибуты самого виджета (`theme`, `display`, `type` и другие) создаёт клиент, сайт их не задаёт. Внешний вид меняют CSS-переменными.

## 5. CSP

Сайт с Content Security Policy нужны такие строки. Пример для сайта на `https://site.ru` и шлюза Pro на `https://forms.site.ru`:

```
script-src 'self';
connect-src 'self' https://forms.site.ru;
worker-src blob:;
style-src 'self' 'unsafe-inline';
```

| Директива | Зачем |
| --- | --- |
| `script-src 'self'` | Клиент и виджет — скрипты с домена сайта. Подключайте клиент npm-пакетом или файлами `formgate.js` и `formgate-pow-widget.js` с того же домена, не с хоста шлюза. |
| `connect-src` | Клиент запрашивает метку и отправляет заявку на адрес формы. С Lite он на домене сайта, `'self'` хватает. С Pro добавьте хост шлюза. |
| `worker-src blob:` | **Только режим «виджет».** Виджет запускает Web Workers из `blob:`-адреса. Режим «невидимо» воркеров не создаёт, ему директива не нужна. Без `worker-src` браузер берёт `script-src`: тогда добавьте туда `blob:`. |
| `style-src 'unsafe-inline'` | **Только режим «виджет».** Виджет вставляет свои стили элементом `<style>` в `<head>`. Строгая политика: положите nonce в `<meta name="csp-nonce" content="…">`, виджет повесит его на `<style>`. |

Внешних хостов (CDN, сервисов капчи) в политике нет.

## 6. Форма без клиента, спам-лог, выпуск

Простая HTML-форма без клиента не присылает ни `__token`, ни `__pow`. С `require_pow` такая заявка попадает в спам-лог с причиной `pow_missing`. Если нет `__token`, а `__pow` есть, причина — `token_missing`.

Причины, связанные с proof-of-work:

| Причина | Когда | Что делать |
| --- | --- | --- |
| `pow_missing` | Нет `__pow`: форма без клиента, клиент не решил задачу (небезопасный контекст, не загрузился виджет, ошибка решателя) | Подключить клиент; для виджета проверить файлы и CSP; сайт открывать по HTTPS |
| `pow_invalid` | `__pow` не читается, решение неверное, взято у другой метки или просрочено | Обычно подделка или старая вкладка; клиент сам берёт новую пару после отправки |
| `token_unavailable` | Клиент не смог получить метку за ~10 секунд (шлюз недоступен), `__pow` нет | Проверить доступность шлюза и CORS |

Остальные причины метки (`too_fast`, `expired`, `reused`, `bad_signature`) — `docs/integration.md`, раздел 6.

Заявка с этими причинами могла прийти от человека, поэтому оператор может её выпустить.

- **Pro:** `docker compose exec web php bin/formgate spam:list` показывает записи с причиной; `docker compose exec web php bin/formgate spam:release <id>` отправляет запись в доставку (`docs/pro-setup.md`, раздел 7).
- **Lite:** команды выпуска нет. Записи спам-лога лежат в хранилище (`docs/lite-setup.md`, раздел 6).

## 7. Как проверить сайт

1. Self-check показывает настройки. Lite: страница или JSON по секретной ссылке, поле `token.pow_required` и `token.pow_max_number` (`docs/lite-setup.md`, раздел 4). Pro: `project:self-check <ключ>`.
2. Задача выдаётся: команда `curl` из раздела 2 возвращает `challenge`.
3. Заявка проходит. На тестовом окружении Lite задайте `FORMGATE_TEST_DELIVERY_FILE=/путь/к/файлу.jsonl` (`docs/lite-setup.md`, раздел 5): шлюз не вызывает каналы, а дописывает каждую принятую заявку в файл одной JSON-строкой. Отправьте форму из браузера и проверьте, что в файле появилась строка. Спам в файл не попадает, поэтому отсутствие строки значит, что заявка ушла в спам-лог. Переменную не задавайте на рабочем сайте.
4. Заявка без клиента ловится. Простой `POST` без `__token` отвечает «успех», но строки в файле нет, а в спам-логе есть запись `pow_missing`:

   ```sh
   curl -s -X POST -H 'Origin: https://site.ru' -d 'phone=+79991234567' -d 'consent=1' '<адрес формы>'
   ```

**Чек-лист перед запуском:**

- [ ] `require_token` и `require_pow` включены; `GET ?token` отдаёт `challenge`.
- [ ] Клиент подключён на **каждой** форме проекта.
- [ ] Сайт открыт по HTTPS.
- [ ] Для `formgate.js` рядом лежит `formgate-pow-widget.js` (если есть формы с `data-formgate-pow="widget"`).
- [ ] CSP по разделу 5; в консоли браузера нет ошибок CSP.
- [ ] Виджет стоит в нужном месте, читается в светлой и тёмной теме, не вылезает за экран на мобильном.
- [ ] Тестовая заявка из браузера дошла; повторите её с другим текстом (одинаковая заявка в течение 10 минут — дубль).
- [ ] Спам-лог после теста не пополнился записями `pow_missing` и `pow_invalid` от ваших тестов.

## 8. Если не работает

| Что видно | Причина и решение |
| --- | --- |
| Все заявки в спам-логе с `pow_missing` | Клиент не решает задачу. Проверьте: сайт по HTTPS; форма привязана (`data-formgate`, подключён скрипт); консоль браузера без ошибок |
| `pow_missing` только у форм с `data-formgate-pow="widget"` | Не загрузился модуль виджета: нет `formgate-pow-widget.js` рядом с `formgate.js` (404) или CSP блокирует скрипт, `blob:`-воркер или стили (раздел 5) |
| `pow_invalid` у честных посетителей | Сменили `FORMGATE_TOKEN_SECRET` (Pro) или ключ подписи Lite, пока страницы были открыты; или посетитель держал форму дольше `token_max_seconds` |
| Виджета нет на странице | Нет `data-formgate-pow="widget"` на форме, форма не привязана, либо модуль виджета не загрузился (см. строку выше). Элемент `altcha-widget` есть в DOM формы, когда модуль загружен |
| `require_pow` отклонён при настройке | Не включён `require_token`, либо `pow_max_number` вне диапазона `1000`–`10000000` |
| Форма долго «думает» на телефоне | Уменьшите `pow_max_number` |
| В Lite изменения не видны | Self-check покажет, какой файл настроек Lite нашёл (`where`) |
