# Установка Lite

Документ для оператора: как положить Lite рядом с сайтом, где держать файл настроек и как проверить, что всё работает.

## 1. Что нужно

- PHP 8.1 или новее.
- Для отправки в каналы — `curl` или `allow_url_fopen`.
- Расширение `mbstring`.
- Расширение `pdo_sqlite` желательно: с ним заявки хранятся в SQLite, без него — в файлах JSONL.

## 2. Куда положить

1. Скопируйте папку Lite рядом со статикой сайта, например в `public_html/formgate/`.
2. Положите один файл настроек **выше корня сайта**, чтобы веб-сервер не мог его отдать: `formgate.php` рядом с папкой `public_html`.
3. Откройте self-check (раздел 4).

Корень сайта считается от места, где живёт сайт (document root веб-сервера), а не от папки Lite. Lite в `public_html/formgate/` ищет файл рядом с `public_html`, а не рядом с `formgate`.

## 3. Где Lite ищет файл настроек

Lite берёт первый найденный файл по порядку:

| № | Место |
| --- | --- |
| 1 | переменная окружения `FORMGATE_SETTINGS` |
| 2 | `formgate.php` выше корня сайта |
| 3 | `formgate.php` ещё выше, если сайт лежит в `releases/<id>` (схема деплоя с папкой релизов) |
| 4 | `formgate.php` внутри папки Lite |

Если переменная окружения задана, а файла по её пути нет, это ошибка: Lite не ищет дальше.

Место 4 — только для хостингов, где выше корня сайта писать нельзя. `.htaccess` закрывает файл от веба, а PHP-файл сервер не отдаёт как текст, но self-check предупреждает, что это менее безопасно. На nginx закройте `formgate.php` и файлы хранилища (`formgate-*`) сами.

Файл возвращает массив: см. `lite/src/Settings/defaults.php`, там все ключи с пояснениями. Обязательны `project.domains` и хотя бы один канал в `channels`. `project.thank_you_url` и `project.error_url` обязательны, пока `project.plain_form_answer` равно `redirect` (так по умолчанию). При `json` обычная форма получает JSON-ответ, а не `303`.

### Если файла нет или он неверный

Посетитель получает `500 server_error`, причина пишется в `error_log`. Если выше корня сайта можно писать, Lite сохраняет поля заявки там со статусом `failed`, чтобы заявка не пропала.

## 4. Self-check

Self-check — страница, которую открывает оператор по секретной ссылке. Задайте в файле настроек ключ:

```php
'selfcheck_key' => 'длинная-случайная-строка',
```

и откройте `GET https://<сайт>/formgate/submit.php?key=длинная-случайная-строка`.

Страница показывает:

- версию PHP (нужна 8.1+);
- `curl` или `allow_url_fopen`;
- `mbstring` и `pdo_sqlite`;
- путь к файлу настроек; предупреждение, если файл внутри корня сайта;
- вид хранилища: `sqlite`, `jsonl` или `guarded jsonl`;
- результат тестовой отправки в каждый канал и в каждый способ отправки email.

Если включена тестовая доставка (раздел 5), страница предупреждает об этом.

Тестовое сообщение помечено как тест (`TEST: Formgate self-check`) и в хранилище не попадает. Тест в Bitrix24 создаёт настоящий лид с заголовком `TEST: Formgate self-check`: удалите его в CRM.

С неверным или пустым ключом и при незаданном `selfcheck_key` ответ — `404` с пустым телом. `GET` без параметра `key` — не self-check: ответ `405 method_not_allowed`, как на любой запрос не методом `POST`. Не публикуйте ссылку с ключом.

### Self-check в JSON

`GET …?key=<ключ>` с заголовком `Accept: application/json` отдаёт `200` JSON вместо страницы. Тестовых сообщений он не шлёт и секретов (токен, пароль, webhook, ключ) не содержит. Поля:

- `settings` — `found`, `where` (`env`, `above_site_root`, `above_releases`, `lite_folder`), без пути к файлу;
- `domains`;
- `channels` — для каждого `number`, `type`, `name` и `configured` (обязательные опции заданы);
- `storage` — `backend` и `writable`;
- `token` — `required`, `key_present`, `min_seconds`, `max_seconds`;
- `test_delivery` — `true`, если включена тестовая доставка;
- `findings` — список `label`, `level` (`ok`, `warning`, `fail`), `detail`.

Неверный или пустой ключ — `404` с пустым телом, `GET` без `key` — `405`, как и для страницы.

## 5. Тестовая доставка

Только для автотестов сайта. Если у процесса Lite задана переменная окружения `FORMGATE_TEST_DELIVERY_FILE` (рядом с `FORMGATE_TEST_NOW`, которую тоже ставят только тесты), Lite не вызывает каналы. Каждую заявку, которая была бы доставлена, он дописывает в этот файл одной JSON-строкой: `time` (ISO 8601), `request_id` (идентификатор заявки, раздел 6), `form`, `fields`, `service` (`subject`, `reply_to`, `redirect`), `consent` и `channels` маршрута (`number`, `type`, `name`). Заявка сохраняется как доставленная, посетитель получает обычный успех. Спам и дубликаты в файл не попадают.

Если файл не записать, ответ тот же, что при сбое доставки: `500 delivery_failed`, причина в `error_log`. Self-check (страница и JSON) предупреждает, пока переменная задана. Не задавайте её на рабочем сайте.

## 6. Что хранит Lite

Lite хранит заявки, спам-лог, счётчики лимита частоты, хеши для проверки дублей и ключ подписи метки времени. Место и вид хранилища выбираются сами, в таком порядке:

| Вид | Когда | Где |
| --- | --- | --- |
| `sqlite` | выше корня сайта можно писать и есть `pdo_sqlite` | `formgate.sqlite` выше корня сайта |
| `jsonl` | выше корня можно писать, `pdo_sqlite` нет | файлы `formgate-*.jsonl` выше корня сайта |
| `guarded jsonl` | выше корня писать нельзя | файлы `formgate-*.php` в папке Lite; первая строка каждого — `<?php exit; ?>`, поэтому веб не покажет данные |

Вид хранилища показывает self-check (раздел 4). Срок хранения заявок и спам-лога задаёт `project.retention_days` в файле настроек; без него Lite не удаляет ничего. За персональные данные в хранилище отвечает тот, кто поставил Lite.

Каждая запись (заявка или запись спам-лога) хранит поля, которые прислал сайт, и четыре значения, которые шлюз записывает сам:

| Значение | Что это |
| --- | --- |
| `request_id` | случайный идентификатор заявки (22 символа base64url); он же есть в строке тестовой доставки (раздел 5) |
| `ip` | IP посетителя; за доверенным прокси (`project.trusted_proxies`) берётся клиент из `X-Forwarded-For`, иначе адрес соединения |
| `user_agent` | заголовок `User-Agent`, не длиннее 512 символов |
| `origin_host` | хост из `Origin`, а без него из `Referer`, строчными буквами |

В каналы эти значения не уходят. В Pro их хранят очередь и спам-лог (`docs/pro-setup.md`, раздел 4, «Очередь, повторы, хранение и оповещения»). Запись, сделанная до появления этих значений, хранит их пустыми.

Заявка получает статус: `delivered` (приняли все каналы маршрута), `partial` (часть) или `failed` (ни один; посетитель видит `500 delivery_failed`). Недоставленный канал Lite не повторяет: очереди нет. Если канал отказал, оператор получает оповещение в Telegram, когда в настройках задан бот `alert`.

## 7. Каналы

Канал — запись в списке `channels` файла настроек: `['type' => …, 'options' => […], 'name' => …]`; необязательное `name` позволяет частным случаям (`cases`) ссылаться на канал по имени, а не по номеру. Опции, которых нет у канала, берутся из `channel_defaults` (`lite/src/Settings/defaults.php`). Те же опции задаёт Pro командой `project:channel:add -o имя=значение` (`docs/pro-setup.md`, раздел 4).

| Тип | Обязательные опции | Остальные |
| --- | --- | --- |
| `telegram` | `bot_token`, `chat_id` | `api_url` (по умолчанию `https://api.telegram.org`), `timeout_seconds` (10) |
| `email` | `to` (адрес или список), `methods` | `timeout_seconds` (10), `default_subject` (тема, когда нет `__subject`) |
| `bitrix24` | `webhook_url` (входящий вебхук) | `map` (поле заявки → поле лида), `timeout_seconds` (10), `default_title` (`TITLE` лида, когда нет `__subject`) |

`methods` почты — список способов, Lite пробует их по порядку, пока один не примет письмо:

- `['type' => 'smtp', 'host' => …, 'port' => …, 'encryption' => 'ssl'|'tls'|'starttls'|'none', 'from' => …]` и необязательные `login`, `password`;
- `['type' => 'mail', 'from' => …]` — PHP `mail()` через sendmail хостинга.

Каждое письмо несёт заголовок `X-Tags: formgate`, по нему письма можно фильтровать в почтовом ящике. Что из заявки попадает в сообщение и в лид Bitrix24 — `docs/integration.md`, раздел 3. Бот оповещений (`alert`: `bot_token`, `chat_id`) задаёт те же опции, что канал `telegram`.
