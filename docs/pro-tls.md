# HTTPS для Pro на публичном сервере (профиль tls)

## Когда включать

Профиль `tls` нужен, когда Pro стоит на публичном сервере и формы шлют запросы с сайтов по HTTPS. Caddy стоит перед `web`, сам получает сертификат Let's Encrypt для вашего домена и продлевает его.

Не включайте профиль, если HTTPS уже даёт другой слой (например, обратный прокси или VPN). Без профиля `web` отдаёт обычный HTTP на `FORMGATE_WEB_PORT`, как раньше.

## Что нужно заранее

1. Домен, например `forms.example.com`. Его A-запись (и AAAA, если есть IPv6) указывает на IP сервера.
2. Порты 80 и 443 открыты в файрволе сервера и у провайдера. Порт 80 нужен для проверки домена Let's Encrypt.
3. Docker и Docker Compose на сервере.

## Как включить

1. В `.env` задайте домен и профиль:

   ```
   FORMGATE_DOMAIN=forms.example.com
   COMPOSE_PROFILES=tls
   ```

   Вместо правки `.env` можно запустить `install.sh --tls`.
2. Запустите: `docker compose up -d`.
3. Проверьте: `curl https://forms.example.com/health`. Первый сертификат Caddy получает за минуту-две.

Сертификаты лежат на томе `caddy_data`: после перезапуска Caddy не просит их заново.

## Если не работает

- `docker compose logs caddy` показывает ошибки получения сертификата.
- Чаще всего причина — DNS ещё не указывает на сервер или порт 80 закрыт.
- Без `FORMGATE_DOMAIN` Caddy не стартует. Пока профиль выключен, переменная не нужна.
